# Інструкція з експлуатації: World Clock (ESP32-S3)

Дана інструкція описує принцип роботи, апаратну частину, налаштування та обслуговування пристрою **World Clock** на базі мікроконтролера **ESP32-S3** та дисплейного модуля **JC4827W543**.

---

## 1. Призначення пристрою

**World Clock** — це настільний розумний годинник, що поєднує три функції:

*   **Світовий годинник** — відображення поточного часу у 5 різних містах світу одночасно з кольоровими індикаторами робочого часу для кожного міста.
*   **Метеостанція** — поточні значення температури, вологості (за наявності BME280) та тиску з датчика BMP/BME280.
*   **Журнал метеоданих** — автоматичне записування вимірювань кожні 5 хвилин із утриманням за останні 15 діб та переглядом графіків через веб-інтерфейс.

Пристрій автоматично синхронізує час через Інтернет за допомогою протоколу NTP (Network Time Protocol) та відображає його на кольоровому дисплеї за допомогою графічної бібліотеки **LVGL**. Конфігурація пристрою здійснюється через веб-панель керування.

---

## 2. Апаратна та програмна архітектура

Пристрій побудовано на базі сучасних та потужних технологій:

*   **Мікроконтролер**: ESP32-S3-DevKitC-1-N8 (8 MB Flash, підтримка PSRAM).
*   **Дисплейний модуль**: JC4827W543 з діагоналлю 4.3 дюйма та роздільною здатністю **480x272** пікселів.
    *   Драйвер дисплея: **NV3041A**, підключений через швидкісну шину **QSPI** (піни: CS=45, SCK=47, D0=21, D1=48, D2=40, D3=39).
    *   Керування підсвіткою (Backlight): GPIO 1.
*   **Метеодатчик (опціональний)**: **BMP280** (температура + тиск) або **BME280** (температура + тиск + вологість). Підключається до I2C-шини: **SDA = GPIO17, SCL = GPIO18**. Тип чіпа розпізнається автоматично за регістром chip ID (`0x58` = BMP280, `0x60` = BME280).
*   **Контролер живлення (опціональний)**: **IP5306** (I2C-адреса `0x75`) — для плат із батареєю. Забезпечує індикацію заряду та стану заряджання.
*   **Графічний інтерфейс**: Графічна бібліотека **LVGL v8.4.0** у поєднанні з **Arduino_GFX**.
*   **Файлова система**: **LittleFS** (розділ 896 КБ у partition table `huge_app.csv`). Зберігає веб-інтерфейс та журнал метеоданих `/meteo.bin`.
*   **Енергонезалежна пам'ять**: Бібліотека **Preferences** (NVS, 20 КБ) для збереження конфігурації WiFi, годинників, робочих годин та інших налаштувань.

## 3. Життєвий цикл та режими роботи

При ввімкненні живлення пристрій проходить наступні етапи запуску:

1.  **Ініціалізація системи**: ініціалізуються Preferences, екран NV3041A, LVGL, монтується LittleFS, створюється головний екран LVGL.
2.  **Ініціалізація журналу метеоданих**: завантажується `/meteo.bin` у RAM-кільце на 4320 записів; за наявності застарілого формату відбувається автоматична міграція (див. розділ 7).
3.  **Ініціалізація датчиків**: `bmeInit()` сканує I2C-шину та визначає тип датчика; `ip5306Init()` опитує контролер живлення (працює тільки після `bmeInit()`, оскільки вони поділяють ту саму шину).
4.  **Запуск WiFi та Веб-сервера**:
    *   **Режим клієнта (Station Mode / STA)**: Якщо в Preferences збережено назву мережі (SSID), пристрій намагається підключитися до неї протягом 30 секунд. Після успішного підключення він отримує IP-адресу і запускає NTP-клієнт для синхронізації часу з UTC через сервери `pool.ntp.org`, `time.nist.gov` та `time.google.com`. Після синхронізації починається відлік часу, і екран оновлюється кожну секунду.
    *   **Режим точки доступу (Access Point / AP)**: Якщо дані WiFi відсутні або підключення не вдалося за 30 секунд, пристрій запускає власну відкриту WiFi мережу:
        *   **SSID (назва мережі)**: `WorldClock_Setup`
        *   **Пароль**: відсутній
        *   **IP-адреса для доступу**: `192.168.4.1`
        *   У цьому режимі пристрій очікує, поки користувач підключиться і налаштує WiFi через веб-інтерфейс.

## 4. Інструкція користувача з налаштування

### Крок 1. Перше підключення до пристрою
1.  Увімкніть живлення пристрою. На екрані з'явиться вітальне вікно та статус підключення: `WiFi : Waiting`, `NTP : Waiting`, `IP : ---`.
2.  Оскільки пристрій ще не підключений до вашої мережі, він перейде в режим точки доступу.
3.  На смартфоні або комп'ютері відкрийте список доступних мереж WiFi та підключіться до мережі `WorldClock_Setup`.
4.  Відкрийте браузер і перейдіть за адресою: `http://192.168.4.1/`.

### Крок 2. Налаштування мережі WiFi
1.  У веб-інтерфейсі перейдіть на вкладку **Network**.
2.  Введіть назву вашої WiFi мережі у полі **WiFi SSID**.
3.  Введіть пароль від вашої WiFi мережі у полі **Password**.
4.  За потреби увімкніть статичну IP-конфігурацію (замість DHCP) і вкажіть IP / маску / шлюз / DNS.
5.  Натисніть кнопку **Save**. Після цього пристрій збереже налаштування та перезавантажиться для підключення.
6.  Після успішного підключення на екрані пристрою замість `IP : ---` з'явиться його реальна IP-адреса у вашій локальній мережі (наприклад, `192.168.1.105`). Запишіть її.

### Крок 3. Налаштування годинників міст
Тепер, коли пристрій підключено до Інтернету, ви можете налаштувати міста, які відображатимуться на екрані:
1.  Підключіть ваш смартфон чи комп'ютер до тієї ж WiFi мережі, що й годинник.
2.  Введіть у браузері IP-адресу, яку показує екран пристрою (наприклад, `http://192.168.1.105/`).
3.  Перейдіть на вкладку **Clocks**.
4.  Налаштуйте до 5 годинників. У полі **City** для кожного годинника введіть назву міста.
5.  Для кожного міста вкажіть **робочі години** (початок/кінець) та прапорці суботи/неділі — це визначає стан індикатора (див. розділ 5.2).
6.  Натисніть кнопку **Save**. Годинник одразу оновить час на екрані.

> [!IMPORTANT]
> **ПРАВИЛА ВВЕДЕННЯ НАЗВ МІСТ:**
> Назви міст необхідно вводити англійською мовою точно так, як вони вказані в базі даних пристрою. Якщо назву міста буде введено неправильно або іншою мовою, годинник покаже `--:--:--`.
> 
> **Популярні назви міст з бази даних:**
> *   `Kyiv` (Київ)
> *   `London` (Лондон)
> *   `New York` (Нью-Йорк)
> *   `Tokyo` (Токіо)
> *   `Valencia` / `Madrid` / `Barcelona` (Валенсія, Мадрид, Барселона)
> *   `Paris` (Париж)
> *   `Berlin` (Берлін)
> *   `Dubai` (Дубай)

## 5. Екранний інтерфейс

### 5.1. Режими відображення

Пристрій підтримує три режими, які вибираються на веб-вкладці **Display**:

| Режим | Константа | Поведінка |
|---|---|---|
| **Alternate** | `DISPLAY_MODE_ALTERNATE` (за замовч.) | Годинник та метео перемикаються кожні 30 с. |
| **Clock Only** | `DISPLAY_MODE_CLOCK_ONLY` | Тільки світові годинники. |
| **Env Only** | `DISPLAY_MODE_ENV_ONLY` | Тільки метеодані (Environment). |

Там само налаштовується яскравість підсвітки (0–100 %) та вибір міста-еталона (reference city) для попереджень про перетин часу.

### 5.2. Індикатори робочого часу (маркери)

Біля кожного з п'яти годинників виводиться два маркери:

*   **Малий круг** (ліворуч від міста) — індикатор стану робочого часу.
*   **Квадрат** (праворуч від міста, перед часом) — дублює стан крупніше.

Колір маркера визначається поточним часом у відповідному місті та налаштованим графіком:

| Колір | HEX | Значення |
|---|---|---|
| 🟥 Червоний | `0xFF0000` | Неробочий час. |
| 🟩 Зелений | `0x388E3C` | Робочий час (активний). |
| 🟨 Жовтий | `0xFBC02D` | Менше 30 хвилин до кінця робочого часу. |
| 🟦 Синій | `0x0288D1` | Менше 30 хвилин до початку робочого часу. |

Графік задається на веб-вкладці **Clocks**: час початку й кінця, а також прапорці роботи у суботу та неділю — окремо для кожного міста.

### 5.3. Вигляд метеоданих (Environment View)

У режимі метео на екрані показуються три рядки (колонка лейблів ліворуч, значення праворуч):

| Параметр | Колір тексту | Примітка |
|---|---|---|
| **Temperature** | зелений (`0x00E676`) | поточна температура, °C. |
| **Pressure** | синій (`0x448AFF`) | атмосферний тиск, hPa. |
| **Humidity** | зелений (`0x00E676`) | відносна вологість, %. **Приховується**, якщо датчик — BMP280 (без вологості). |

## 6. Поведінка пристрою при відключенні датчика BMP/BME-280

Датчик температури/тиску (BMP280) або температури/тиску/вологості (BME280) підключається до I2C-шини (**SDA = GPIO17, SCL = GPIO18**) і є **необов'язковим вузлом**. Пристрій повністю працездатний і без нього — відключення датчика не блокує запуск і не впливає на роботу годинника.

### 6.1. Коли виявляється відключення

Детекція відбувається **лише під час завантаження** (увімкнення живлення або reset). У функції `bmeInit()` виконується повне сканування I2C-шини (адреси 1–126). Якщо жодного пристрою не знайдено, у послідовний порт (115200 бод) виводиться діагностика:

```
BME/BMP280: no I2C devices found! Check wiring/power/pull-ups.
BME280 init failed (sensor offline).
```

Після цього датчик позначається як відсутній, канал вологості — як недоступний. Під час роботи (hot-plug) повторна детекція **не виконується**: повторне підключення датчика «на льоту» не розпізнається.

### 6.2. Що продовжує працювати

*   **Годинник, WiFi, NTP, веб-сервер, дисплей** — повністю працездатні. Основна функція пристрою не порушується.
*   **IP5306** (контролер живлення/батареї, адреса `0x75`) — поділяє ту саму I2C-шину, але визначається незалежно, тому індикатор рівня заряду далі працює.
*   **Історія метеоданих** — наявні записи у файлі `/meteo.bin` зберігаються. Нові вимірювання до журналу не додаються, поки датчик відсутній.

### 6.3. Відображення на екрані

У режимі перегляду середовища (Environment View) рядок вологості автоматично приховується, а замість поточних значень температури та тиску показуються прочерки:

| Поле        | Значення на екрані |
|-------------|--------------------|
| Temperature | `--.- C`           |
| Pressure    | `----.- hPa`       |
| Humidity    | (поле приховано)   |

Перемикання між виглядом годинника та середовищем (30 с / 30 с у режимі `ALTERNATE`) зберігається — просто у вигляді середовища будуть показані прочерки.

### 6.4. Веб-інтерфейс

*   `GET /api/sensor` повертає `{"active":"none","hasHumidity":false}`.
*   `GET /api/meteo` продовжує віддавати раніше збережену історію метеоданих.

### 6.5. Відновлення роботи датчика

Після повторного підключення датчика **необхідне перезавантаження живленням** (або reset). Тільки тоді `bmeInit()` знову просканує шину та ідентифікує чіп за регістром `chip ID`:

*   `0x58` — BMP280 (температура + тиск, без вологості),
*   `0x60` — BME280 (температура + тиск + вологість).

Ручна конфігурація типу датчика не потрібна — визначення відбувається автоматично.

## 7. Журнал метеоданих (Meteo Log)

### 7.1. Параметри запису

*   **Інтервал:** 5 хвилин (`METEO_LOG_INTERVAL_SEC = 300`).
*   **Утримання:** 15 діб (`METEO_LOG_RETENTION_DAYS = 15`).
*   **Ємність:** 288 проб/добу × 15 = **4320 записів**.
*   **Формат запису:** 10 байт (час + температура × 100 + вологість × 10 + тиск × 10).
*   **Зберігання:** RAM-кільце 43 200 байт + файл `/meteo.bin` 43 206 байт у LittleFS.
*   **Стратегія запису:** кожна проба пише лише свій 10-байтовий слот у файл (in-place), що зводить знос flash до мінімуму (~10+ років ресурсу).
*   **Поведінка при заповненні:** найстаріша проба циклічно витісняється новою (FIFO).

### 7.2. Перегляд історії

У веб-інтерфейсі відкрийте вкладку **Meteo** — там доступні:

*   Поточні значення з датчика (температура/тиск/вологість).
*   Графіки за останні 15 діб з децимацією до 600 точок для швидкої завантажки.
*   Можливість фільтрації діапазоном часу (`from`/`to` у Unix-секундах через API `GET /api/meteo`).

### 7.3. Сумісність форматів

При оновленні прошивки зі старої версії (формат `"METE"`) на нову (`"METF"`) відбувається **автоматична міграція** без втрати історії. Збережені у старому форматі записи зчитуються у RAM, після чого файл переписується у новому форматі з пре-алокацією повного розміру.

### 7.4. Налаштування параметрів логу (для розробників)

Параметри можна перевизначити через `build_flags` у `platformio.ini`:

```ini
build_flags =
    -DMETEO_LOG_INTERVAL_SEC=120     ; 2 хв замість 5
    -DMETEO_LOG_RETENTION_DAYS=30    ; 30 діб замість 15
```

Докладний опис реалізації — у файлі [`docs/meteo_log_UA.md`](docs/meteo_log_UA.md).

## 9. Важлива інформація для розробників

Веб‑сервер (`src/web/web_server.cpp`) роздає головну сторінку `/index.html` через явний маршрут, а всі інші статичні файли (`/style.css`, `/app.js`) — через `server.serveStatic("/", LittleFS, "/")`. Реєстр маршрутів повинен залишатися саме в такому порядку: спочатку `server.on("/", ...)`, потім `server.serveStatic(...)`, потім `server.onNotFound(...)`, і наприкінці `webApiInit(server)`.

## 10. Інструкція з прошивки та розгортання проекту

Для розробників, які хочуть перекомпілювати та оновити прошивку пристрою за допомогою **PlatformIO**:

### Крок 1. Підготовка середовища
1.  Встановіть **Visual Studio Code**.
2.  Встановіть розширення **PlatformIO IDE** в VS Code.
3.  Відкрийте папку проекту `WorldClock` у VS Code.

### Крок 2. Збірка та завантаження прошивки
1.  Підключіть модуль ESP32-S3 до комп'ютера за допомогою USB-кабелю (через порт USB/CDC або UART).
2.  У лівій панелі PlatformIO оберіть проект та натисніть **Build** (або виконайте `pio run` в терміналі) для перевірки збірки.
3.  Натисніть **Upload** (або `pio run -t upload`) для прошивки двійкового файлу в мікроконтролер.

### Крок 3. Завантаження образу файлової системи (ОБОВ'ЯЗКОВО)
Веб-інтерфейс зберігається у папці `data/`. Його потрібно окремо прошити в пам'ять LittleFS:
1.  В інтерфейсі PlatformIO знайдіть меню **Platform** -> **Upload Filesystem Image** (або виконайте команду `pio run -t uploadfs` в терміналі).
2.  Ця дія створить образ LittleFS з файлами `index.html`, `style.css`, `app.js` та завантажить його у виділений flash-розділ пристрою.

> [!NOTE]
> Журнал метеоданих `/meteo.bin` зберігається в тому самому розділі LittleFS, тому при `uploadfs` він **буде стертий**. Перед перепрошивкою файлової системи збережіть цей файл через веб-інтерфейс або завантажте його з флешки, якщо потрібно зберегти історію.

## 11. Технічна інформація про змінні та конфігурацію

Усі налаштування зберігаються у NVS (Preferences, namespace `worldclock`). Версія схеми — `version = 3`; при розбіжності застосовуються значення за замовчуванням.

### 11.1. Мережа

| Ключ | Тип | За замовч. | Опис |
|---|---|---|---|
| `wifi_ssid` | String | `""` | Назва мережі WiFi. |
| `wifi_pass` | String | `""` | Пароль WiFi. |
| `wifi_dhcp` | Bool | `true` | Використовувати DHCP (true) або статичну IP (false). |
| `wifi_ip` | String | `192.168.1.100` | Статична IP-адреса. |
| `wifi_subnet` | String | `255.255.255.0` | Маска підмережі. |
| `wifi_gw` | String | `192.168.1.1` | Шлюз за замовч. |
| `wifi_dns` | String | `8.8.8.8` | DNS-сервер. |

### 11.2. Годинники

| Ключ | Тип | За замовч. | Опис |
|---|---|---|---|
| `clk_count` | uint8 | `5` | Кількість активних годинників (1–5). |
| `city0`..`city4` | String | `Kyiv`, `Valencia`, `Delhi`, `Washington`, `Tokyo` | Назва міста для годинника X. |
| `tz0`..`tz4` | uint16 | 0..4 | Індекс часового поясу (зарезервовано). |
| `ref_city` | uint8 | `0` | Індекс міста-еталона для попереджень. |

### 11.3. Робочі години (для маркерів)

| Ключ | Тип | За замовч. | Опис |
|---|---|---|---|
| `ws0`..`ws4` | uint16 | `540` (09:00) | Початок робочого часу, хвилини від 00:00. |
| `we0`..`we4` | uint16 | `1080` (18:00) | Кінець робочого часу. |
| `sat0`..`sat4` | Bool | `false` | Працює у суботу. |
| `sun0`..`sun4` | Bool | `false` | Працює у неділю. |
| `overlap` | uint16 | `60` | Порог попередження про перетин часу, хвилини. |

### 11.4. Дисплей та система

| Ключ | Тип | За замовч. | Опис |
|---|---|---|---|
| `disp_mode` | uint8 | `0` (ALTERNATE) | Режим відображення: 0=ALTERNATE, 1=CLOCK_ONLY, 2=ENV_ONLY. |
| `brightness` | uint8 | `100` | Яскравість підсвітки, %. |
| `ntp_srv` | String | `pool.ntp.org` | Адреса NTP-сервера. |
| `language` | String | `EN` | Мова інтерфейсу (`EN`/`UA`). |
| `version` | uint16 | `3` | Версія схеми Preferences. |

Скидання всіх налаштувань до заводських виконується функцією `prefClearAll()` (доступ через веб-вкладку **System**).
